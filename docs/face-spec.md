# 顔アニメーション仕様

## 待機状態

人が検出されていない状態です。

- 背景色は黒 `#000000` にする。
- 目は表示しない。
- 口は表示しない。

## 人が来た時

以下の順番でアニメーションする。

1. 背景色を黒 `#000000` から 90% グレイへ `300ms` で変化させる。
2. 背景色の変化が完了した後、目を閉じた状態から開いた状態へ `200ms` で変化させる。
3. 目を開いた状態で口を表示し、その状態を `200ms` 維持する。
4. 瞬きを 2 回実行する。

## 人がいなくなった時

以下の順番でアニメーションする。

1. 背景色を黒 `#000000` へ `400ms` で変化させる。
2. 背景色の変化が完了した後、目と口を非表示にする。

## 補足

- 人が検出されていない状態では、閉じた目や閉じた口も表示しない。
- 入室時の瞬きは 2 回だけ実行する。

## 現在の実装詳細

`src/main/resources/html/bot.html` の現在の実装では、以下の値と処理方式を使う。

### 開始と停止

- 開始ボタンはトグルとして扱う。
- 停止中のボタン表示は `開始` にする。
- 動作中のボタン表示は `停止` にする。
- 停止時はカメラ、顔検出タイマー、マイク、顔表示状態を停止または初期化する。
- 停止後に処理中の非同期アニメーションが戻ってきても顔を再表示しないように、実行中フラグとアニメーション番号で無効化する。

### カメラと顔検出

- カメラは `facingMode: "user"` を使う。
- カメラ解像度は `1280x720` を理想値として要求する。
- 顔検出処理は `400ms` 間隔で実行する。
- 顔検出モデルは `@vladmandic/face-api` の `TinyFaceDetector` を使う。
- `TinyFaceDetector` の `inputSize` は `416` にする。
- `TinyFaceDetector` の `scoreThreshold` は `0.5` にする。
- 複数の顔が検出された場合は、検出矩形の面積が最大の顔を対象にする。

### 動き検出による顔検出の省略

- 動き検出用のサンプル画像は `96x54` に縮小する。
- 前フレームとの差分で、平均差分が `6.0` 以上、かつ差分 `18` 以上のピクセル比率が `0.04` 以上の場合に「動きあり」と判定する。
- 動きがない場合でも、前回の顔検出から `3000ms` 以上経過していれば顔検出を実行する。

### 人が来た判定

- 顔の幅が映像幅の `0.20` 以上の場合、人が近くにいる候補として扱う。
- 上記の条件を連続 `2` 回満たした場合、人が来たと判定する。
- 人が来たと判定した後、顔イベント `person-entered` を送信する。
- 人がいる状態では、前回送信から `8000ms` 以上経過した場合に顔イベント `person-updated` を送信する。

### 人がいなくなった判定

- 顔が検出されない状態で、最後に顔を検出してから `9000ms` を超えた場合、人がいなくなったと判定する。
- 顔の幅が映像幅の `0.15` 未満の場合、遠い顔として扱う。
- 遠い顔の判定が連続 `12` 回発生した場合、人がいなくなったと判定する。
- 人がいなくなったと判定した後、顔イベント `person-left` を送信する。

### 顔アニメーション

- 背景の 90% グレイは `#e6e6e6` とする。
- 入室時の背景変化は `300ms` の `linear` 遷移にする。
- 退室時の背景変化は `400ms` の `linear` 遷移にする。
- 開眼アニメーションは `200ms` で、閉じ目、30% 開き、60% 開き、全開の 4 段階で表示を切り替える。
- 瞬き 1 回は `320ms` で、閉じ目、30% 開き、60% 開き、全開の 4 段階で表示を切り替える。
- 入室時の 2 回の瞬きの間隔は `160ms` にする。

### 顔イベントの送信内容

- 顔イベントには `eventType`、`eventId`、`clientTimestamp`、`faceWidthRatio`、`faceAreaRatio`、`detectionScore`、`descriptor`、`imageDataUrl` を含める。
- `imageDataUrl` は顔検出矩形の左右上下に、顔幅の `0.3` 倍の余白を付けて切り出す。
- 切り出し画像の最大サイズは `320x320` にする。
- 切り出し画像は JPEG、品質 `0.75` で送信する。

## 実装予定: 複数人物の顔トラッキングと負荷制御

この節は、単一人物を対象とする現在の実装を、複数人物を独立して扱う実装へ変更する仕様である。
この節の実装が完了した時点で、「現在の実装詳細」のうち、最大面積の顔を選択する処理と固定 `400ms` 周期の処理は削除する。

### 処理の分離

顔処理を以下の 3 種類に分離する。

1. 顔検出は、映像中の全顔について顔矩形と検出スコアを取得する。
2. 顔トラッキングは、前回までのトラックと今回の顔矩形を対応付け、同じ映像内の人物に同じ `trackId` を維持する。
3. 顔認識は、68点ランドマークと 128 次元 descriptor を取得し、FaceDB に登録済みの人物と照合する。

顔トラッキングの `trackId` と FaceDB の `personId` は異なる値として扱う。
`trackId` はページ表示からページ終了までだけ有効なブラウザ内のIDであり、FaceDB の人物IDとして保存しない。

### FaceTrack

ブラウザは、検出された人物ごとに次の状態を `Map<trackId, FaceTrack>` で保持する。

| 項目 | 内容 |
|---|---|
| `trackId` | ブラウザが新規トラック作成時に発行する UUID または単調増加する連番 |
| `box` | 最後に検出した顔矩形 `{x, y, width, height}` |
| `velocity` | 顔矩形中心の直近2回の検出時刻に基づく移動量 |
| `descriptor` | 最後に計算した 128 次元の顔特徴量 |
| `lastSeenAt` | 最後に顔を検出した `performance.now()` の値 |
| `lastDescriptorAt` | 最後に descriptor を計算した `performance.now()` の値 |
| `missedFrames` | 連続して対応する顔を検出できなかった回数 |
| `confirmed` | 2回連続で対応する顔を検出した後に `true` とする状態 |
| `personId` | FaceDB 照合結果の人物ID。未照合または未登録時は `null` |

新しいトラックは `confirmed: false` で作成する。
同じトラックへ2回連続で顔を対応付けた時点で `confirmed: true` にする。
`confirmed: false` のトラックについて、入室イベントとサーバへの顔イベントは送信しない。

### トラックと検出顔の対応付け

各顔検出のたびに、既存トラックと今回検出した顔の全組み合わせについて対応コストを算出する。
同じ顔を複数のトラックへ割り当てず、同じトラックに複数の顔を割り当てない。

対応候補は、次の条件をすべて満たす組み合わせに限定する。

- 速度から予測した矩形中心と検出矩形中心との距離が映像対角線の `15%` 以下、または矩形の IoU が `0.1` 以上であること。
- 両方の descriptor が存在する場合、descriptor のユークリッド距離が `0.45` 以下であること。

候補のコストは次の値の合計とする。

```text
位置コスト + サイズ変化コスト + descriptor 距離コスト
```

位置コストは予測中心からの距離を映像対角線で除算した値、サイズ変化コストは顔矩形面積の変化率、descriptor 距離コストはユークリッド距離とする。
候補をコストの昇順に並べ、未割当のトラックと未割当の検出顔を順に対応させる。
同時に追跡する人数が `10` 人を超える場合は、Hungarian algorithm による最小コスト割当へ変更する。

既存トラックへ対応付けられなかった検出顔には、新しい `trackId` を発行する。
顔を対応付けられなかった既存トラックは `missedFrames` を 1 増やす。
最後の検出から `9000ms` 経過したトラック、または顔幅が映像幅の `15%` 未満の状態が12回連続したトラックは終了する。
トラック終了時は、その `trackId` の `person-left` イベントを1回送信する。

### 顔認識の実行条件

顔検出だけでトラックの対応が一意に決まる場合、descriptor を再計算しない。
68点ランドマークと descriptor は、次のいずれかに該当する顔だけで計算する。

- 新規 `trackId` を作成した時。
- 同じトラックの descriptor 計算から `2000ms` 以上経過した時。
- 顔矩形の面積が、descriptor を計算した時点の面積から `50%` 以上変化した時。
- 位置とサイズだけでは複数トラックへの対応を確定できない時。

descriptor を取得した後、FaceDB の照合を実行する。
FaceDB との照合は descriptor のユークリッド距離が `0.45` 以下の登録サンプルを一致候補とする。
照合結果は `FaceTrack.personId` に保存するが、顔位置だけでのトラッキング結果を変更しない。

### 顔イベント

顔イベントには既存項目に `trackId` を追加する。
各イベントは `trackId` ごとに独立して送信する。

| イベント | 送信条件 |
|---|---|
| `person-entered` | `confirmed: true` になり、顔幅が映像幅の `20%` 以上である時 |
| `person-updated` | 入室済みトラックで、前回送信から `8000ms` 以上経過した時 |
| `person-left` | トラック終了時 |

サーバは `trackId` をセッション内の人物状態を区別する値として使用する。
`trackId` を FaceDB の登録ID、ログインID、または別ページで再利用するIDとして保存しない。

### 実測値による顔処理の負荷制御

顔処理はカメラ、録音、ブラウザVAD、音声再生と同じブラウザスレッドおよびGPU資源を使用する。
ブラウザは顔処理の開始・終了時刻を `performance.now()` で測定し、直近の実測値から実行状態を選択する。
顔処理が実行中の場合、次の顔処理を開始しない。同時実行数は常に `1` とする。

| 状態 | 顔検出周期 | `TinyFaceDetector.inputSize` | descriptor 最短計算間隔 | 適用条件 |
|---|---:|---:|---:|---|
| 0 | `250ms` | `416` | `1000ms` | 直近10回の平均処理時間が `100ms` 未満 |
| 1 | `500ms` | `320` | `1000ms` | 直近10回の平均処理時間が `100ms` 以上 `200ms` 未満 |
| 2 | `1000ms` | `224` | `2000ms` | 直近10回の平均処理時間が `200ms` 以上 `400ms` 未満 |
| 3 | `2000ms` | `160` | `4000ms` | 直近10回の平均処理時間が `400ms` 以上 |

表の descriptor 最短計算間隔は、対応が確定済みのトラックに適用する。
新規トラックの作成時と複数候補の対応を確定できない時は、表の最短計算間隔を待たずに descriptor を計算する。

現在の状態で、直近10回の平均処理時間が顔検出周期の `70%` を3回連続で超えた場合、番号が1大きい状態へ移行する。
直近20回の平均処理時間が顔検出周期の `35%` 未満であり、音声再生の予定時刻との差が `50ms` 未満の場合、番号が1小さい状態へ移行する。
状態0より上へは移行せず、状態3より下へは移行しない。

ブラウザVADが発話開始または発話中を示す間、顔処理開始を最大 `1000ms` 延期する。
音声再生の予定時刻との差が `100ms` を超えた場合、次の顔処理を1回だけ実行しない。
この延期またはスキップ中も、既存トラックの `lastSeenAt` と `missedFrames` は更新しない。
